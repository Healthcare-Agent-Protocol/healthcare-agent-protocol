The repository contains protocol design documents and the HAP-1 proposal.
It does not yet provide an executable healthcare agent service.

## Read the proposed contract

<Steps>
  <Step title="Understand the boundaries">
    Read the [architecture](/docs/architecture) to separate identity, authorization, business operations, and transport.
  </Step>
  <Step title="Review identity and access">
    Read [HAP-1](/spec/identity/hap-1), version `1.0-draft.4`.
    VDCs are required. Trusted intermediaries are optional at the protocol level.
    Start with the payer's discovery requirements and follow its accepted issuance path.
    The payer or its approved intermediary verifies identity and provider delegation, then issues the VDC.
    The payer validates that VDC without reissuing an intermediary's credential.
    Its first scope is `claim.status.read`.
    The [HTTP reference](/spec/identity/hap-1-http) contains the endpoint and field details.
  </Step>
  <Step title="Review both issuance paths">
    The [walkthrough](/spec/identity/hap-1#how-it-works) shows intermediary issuance and direct payer issuance.
    Each payer chooses which paths it accepts and can require an intermediary.
    A direct authentication payload must establish delegated authority, as well as identity.
    The [optional encryption pattern](/spec/identity/hap-1#optional-payload-encryption) can keep lookup identifiers unreadable to the bot.
  </Step>
  <Step title="Review pre-call authentication">
    Read the [voice proposal](/spec/identity/hap-1-voice).
    Discover the payer-selected registration service from its JSON card or authenticated configuration.
    Register through an authenticated API before dialing, then carry the negotiated correlation into the phone call.
    The payer checks the reference itself or gets an authenticated result from its verifier integration.
    Call correlation does not replace the VDC or authorize protected operations.
  </Step>
  <Step title="Define the first business operation">
    Review the [capability catalog](/docs/capabilities) and [open pilot decisions](/docs/roadmap).
    Claim-status request and result schemas remain to be specified.
  </Step>
</Steps>

## Preview the documentation

Use Node.js 24 LTS.

```bash
git clone https://github.com/Healthcare-Agent-Protocol/healthcare-agent-protocol.git
cd healthcare-agent-protocol
npm ci
npm run docs:dev
```

Open `http://localhost:3000`.

## Check a documentation change

```bash
npm run docs:validate
npm run docs:links
```

These commands check the documentation build and internal links.
They do not certify protocol conformance.
